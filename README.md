# 数独（ナンプレ）｜唯一解の生成・候補メモ・次の一手・解析

唯一解を検証して自動生成する数独アプリです。候補メモ、論理的な「次の一手」の提示、任意の問題の解析（解の有無・唯一解判定）まで、**すべてブラウザ内だけで動作**します。外部ライブラリ・CDN・外部画像・生成AI API・サーバー通信は一切使いません。

- **単一ファイル構成**：`index.html` 1枚（HTML + CSS + Vanilla JavaScript）。保存して開くだけで動作します。
- **オフライン動作**：`file://` で開いてもそのまま動きます。ネットワーク不要。
- **PC・タブレット・スマートフォン対応**：マウス・タッチ・キーボードのすべてで操作できます。
- **アクセシビリティ**：`role="grid"` とフォーカス管理、行・列・数字・候補・編集可否・選択・エラー・ヒント対象を含む `aria-label`、`aria-live` 通知、色だけに依存しない状態表現。

## 主な機能

### プレイモード
- 難易度（やさしい／ふつう／むずかしい）を選んで**唯一解の問題を自動生成**（初期配置数の目安：40〜46／32〜39／26〜31個）
- 数字入力・候補メモ・消去・Undo／Redo
- 正解チェック（誤入力の位置のみ表示、正解数字は表示しない）
- 「次の一手」（裸のシングル／行・列・ブロックの隠れたシングル）と理由の提示、ワンクリック適用。正解データが無い盤面では論理判定のみで動作します
- 自動解答（確認あり・Undo可・使用記録は残る）
- 経過時間とヒント使用回数の表示、完成時の成績表示

### 入力・解析モード
- 81マスすべてを自由に編集、候補メモ・Undo／Redo
- 81文字の問題データのインポート（1〜9＝数字、`0` または `.`＝空欄）
- 重複・解の有無・唯一解かどうかの解析（2解発見で打ち切り／未完了を「解なし」と誤判定しない）
- 解の適用（複数解の場合は「複数の解のうち1つを表示します」と明示して確認）
- 解析した唯一解の盤面を **「この盤面をプレイ問題として採用」** でプレイモードの問題にできる（難易度表示は「採用した盤面」になり、正解チェック・自動解答が使えるようになる）

### 盤面は2つのモードで共有
- 盤面・候補メモ・選択・Undo／Redo 履歴は、プレイモードと入力・解析モードで**共有**します。モードを切り替えても盤面は切り替わりません（入力・解析モードで入力した盤面がそのままプレイモードに反映されます）。
- プレイ固有の情報（初期配置・正解・問題ID・難易度・経過時間・ヒント使用回数・自動解答記録・完成状態）は、共有盤面に紐づくメタ情報として保持します。
- 入力・解析モードで**初期配置を書き換えると、生成した問題との対応付けを解除**します（正解チェックと自動解答が使えなくなり、「次の一手」は論理判定のみで動作します）。盤面の入力はそのまま残ります。

### データ管理
- 共有状態（`board` / `notes` / `undo` / `redo` / `selected` / `inputMode`）と、プレイ固有のメタ情報（`initialBoard` / `solutionBoard` / `puzzleId` / `difficulty` / `elapsedMs` / `hintCount` / `revealedHintKeys` / `autoSolved` / `checkActive` / `completed`）を混同しない
- 盤面・候補・履歴・選択は2モードで**共有**し、切り替えても入力は失われない
- 状態は `localStorage` に自動保存（version付き・破損検証つき・復元時に唯一解を再検証）

## 使い方

1. `index.html` を保存し、ブラウザで開く（`file://` で可）。
2. 難易度を選び **「新しい問題」** を押すと生成が始まります。処理中は「キャンセル」できます。
3. 盤面をクリック／タップしてマスを選び、1〜9で数字を入力します。

| 操作 | 方法 |
|---|---|
| マス選択 | クリック／タップ、矢印キー、Home / End、PageUp / PageDown |
| 数字入力 | キーボードの `1`〜`9`、または画面の1〜9ボタン（マスを選んでいなくても、自動で入力できるマスを選んで入力します） |
| 候補メモ | 「候補メモ」ボタンまたは `M` キーで切替 → 数字を押すたびに追加／削除をトグル（3×3固定配置） |
| 消去 | `0` / `Backspace` / `Delete`、「消去」ボタン。候補メモモード中は候補を全消去 |
| Undo / Redo | ボタン、`Ctrl`（`⌘`）+ `Z` ／ `Ctrl`（`⌘`）+ `Shift` + `Z` |
| 次の一手 | 「次の一手」→ 対象マス・数字・手法・理由を表示。「この一手を入力」で適用、「閉じる」で解除 |

**キーボード入力はいつでも使えます。** マスをクリックしていなくても、`1`〜`9` を押すと入力できるマス（空いているマス）を自動で選んで入力します。「新しい問題」で生成した直後や起動直後も、そのままキーボードで入力できます。テキスト入力欄や確認ダイアログの表示中は盤面へ入力しません。矢印キーによるカーソル移動は盤面にフォーカスがあるときだけ働くため、ページのスクロールを妨げません。画面の数字ボタンはタッチ／マウス操作向けに残してあります。

## 構成

```
index.html                     アプリ本体（単一ファイル）
tools/tests.js                 計算ロジックのテスト本体（アプリには含めない）
tools/run-tests.js             計算ロジックのテスト実行（依存なし）
tools/smoke.js                 UI 通し操作テスト（jsdom）
tools/generate-test-boards.py  固定テスト盤面の生成・期待値確定（独立実装）
.github/workflows/test.yml     push / PR 時に自動テストを実行
```

`index.html` は2層に分かれています。

| 層 | `<script id>` | 役割 |
|---|---|---|
| 計算 | `sudoku-core` | DOM を知らない純粋な数独ロジック（検証・候補・解探索・生成・論理ヒント・インポート）。同じソースを Blob から作る Web Worker でも実行する |
| UI | `sudoku-ui` | 状態管理・DOM 描画・イベント・保存・重い処理の駆動 |

重い処理はすべてジェネレータ（`function*`）で実装し、**Web Worker** で実行します。Worker が使えない環境では **12ms ごとにイベントループへ制御を返す分割実行**へ自動フォールバックします（同期の長時間ループは使いません）。処理には識別子を付与し、古い結果が現在の盤面を上書きしないようにしています。

## 実装上の制限事項

- **難易度**は初期配置数による目安であり、厳密な論理難易度を保証しません。生成は試行回数400回・30秒の上限があり、範囲内の問題を作れない場合は**失敗を通知して現在の問題を維持**します（範囲外の問題を黙って提供しません）。
- **次の一手**は裸のシングルと行・列・ブロックの隠れたシングルのみ対応です。一手が見つからない場合も「解なし」「論理的に解けない」とは断定しません。矛盾検査も「候補0個のマス」「未配置数字の配置場所0個」に限られ、あらゆる解なし盤面を検出できるものではありません。
- **Undo / Redo 履歴は200件**が上限で、超えると古い方から破棄します。ヒント使用回数・自動解答記録・経過時間は Undo / Redo では巻き戻りません。
- **解析・検証は20秒**で打ち切り、打ち切りは「解なし」ではなく**判定不能**として扱います。複数解は2個発見した時点で打ち切ります。
- **保存が使えない場合**（localStorage 不可／容量超過）は通知し、以降の自動保存を停止します。プレイは継続できますが、再読み込み後の復元とヒント使用記録の永続化はできません。
- 表示中のヒント（`hintState`）と実行中の処理は保存対象外です。復元後の正解依存機能（正解チェック・自動解答）は、**唯一解の再検証が完了するまで無効**になります。
- 保存形式は version 3（共有盤面モデル）です。version 1／version 2 の保存データは読み込み時に version 3 へ移行します（旧プレイモードの盤面を共有盤面として引き継ぎ、旧入力・解析モードの盤面は共有盤面へ統合し、盤面が一致しない旧解析結果は破棄）。旧形式で表示済みだった一手は再表示時に加算され得る点を通知で明示します。

## デプロイ（GitHub Pages）

このアプリは単一の `index.html` だけで完結するため、ビルド不要でそのまま GitHub Pages に公開できます。

### 方法1：ブランチから公開（設定3クリック・最も簡単）

1. リポジトリの **Settings → Pages** を開く
2. **Source** を `Deploy from a branch`、**Branch** を `main` / `/(root)` にして保存
3. 数十秒後、`https://<ユーザー名>.github.io/<リポジトリ名>/` で公開されます

この方法ではワークフローを使わないため、`.github/workflows/pages.yml` は**不要**です（削除しても構いません）。

### 方法2：GitHub Actions で自動デプロイ

1. **Settings → Pages** で **Source** を `GitHub Actions` にする
2. `main` に push すると `.github/workflows/pages.yml` が `index.html` を公開します（テスト用の `test.yml` とは別ワークフロー）
3. 公開URLは Actions の実行結果、または Settings → Pages に表示されます

> **注意**：Source が「Deploy from a branch」のまま `pages.yml` を実行すると、デプロイのステップが失敗します。方法1と方法2のどちらかに統一してください。

> 公開リポジトリなら GitHub Free で Pages を利用できます。**非公開リポジトリで Pages を使うには GitHub Pro / Team 以上**が必要です（[GitHub Docs](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages)）。
